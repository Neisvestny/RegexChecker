# Проверка регулярных выражений (RegexChecker)

«Помощник» для проверки выражений, используемых в приложениях: определяет, является ли
введённая строка корректным регулярным выражением, и находит его вхождения в тексте
с подсветкой.

**Ключевое ограничение задания:** `System.Text.RegularExpressions` не используется нигде —
парсер, валидатор и движок сопоставления написаны с нуля.

## Возможности

- ввод произвольного выражения (не обязательно регулярного) и произвольной строки;
- кнопка «Проверить» запускает проверку;
- если выражение некорректно — предупреждение с сообщением об ошибке и её позицией
  (каретка в поле выражения переезжает к ошибке);
- если поле пустое — предупреждающее сообщение;
- если выражение найдено в строке — вхождения выделены в поле результата
  (кнопки ◀ ▶ переключают между вхождениями, счётчик показывает позицию и длину);
- если не найдено — сообщение об отсутствии;
- защита от «катастрофического» перебора: бюджет шагов прерывает ресурсоёмкие выражения.

## Структура

```
src/RegexChecker.Core/          # ядро без зависимостей от UI
  Parsing/PatternParser.cs      # рекурсивный спускающий парсер (курсор + позиции ошибок)
  Ast/                          # узлы AST, посетитель, CharClass (диапазоны, дополнения)
  Evaluation/ProgramBuilder.cs  # компилятор AST → программу инструкций (посетитель)
  Evaluation/BacktrackingVm.cs  # backtracking-машина с явным стеком + бюджет шагов
  Evaluation/SearchEngine.cs    # поиск всех непересекающихся вхождений
  RegexHelper.cs                # публичный фасад: Validate / Search
src/RegexChecker.App/           # Avalonia 12 (MVVM: CommunityToolkit.Mvvm)
tests/                          # xUnit
```

## Как это работает

1. **Проверка на регулярность** — `PatternParser` разбирает шаблон по грамматике
   `alternation → concat → quantified → atom`. Любое отклонение (незакрытая группа,
   неверный диапазон, двойной квантор, неизвестный escape, неподдерживаемая конструкция)
   даёт `RegexSyntaxError` с сообщением и позицией.
2. **Компиляция** — `ProgramBuilder` (посетитель по AST) порождает программу инструкций:
   `Char/Any/Class/Split/Jmp/Mark/Progress/AssertStart/AssertEnd/Match`.
   Кванторы раскрываются: обязательные повторения — копиями, ограниченные — через `Split`,
   безграничные — циклом с защитой от пустых итераций (`Mark`/`Progress`).
3. **Сопоставление** — `BacktrackingVm` выполняет программу итеративно, с явным стеком
   отката (рекурсии нет → нет риска переполнения стека) и общим бюджетом в 20 млн шагов.
   Жадные кванторы предпочитают продолжение, ленивые — выход; альтернатива ветвится
   слева направо, как в классических движках.
4. **Поиск** — `SearchEngine` перебирает позиции старта, запоминает непересекающиеся
   вхождения; пустые совпадения не попадают в результат и не блокируют поиск настоящих.

## Поддерживаемый синтаксис

| Конструкция | Пример |
|---|---|
| Литералы, экранирование | `abc`, `\n \t \\ \. \+ \* \( \) \[ \] \{ \} \| \^ \$` |
| Точка | `.` — любой символ, кроме `\n` |
| Классы | `[abc]`, `[a-z]`, `[^0-9]`, `[\d-]` |
| Предопределённые классы | `\d \D \w \W \s \S` |
| Кванторы (жадные/ленивые) | `* + ? {n} {n,} {n,m}` · `*? +? ?? {n,m}?` |
| Якоря | `^` — начало, `$` — конец строки |
| Группы и альтернатива | `(…)`, `(?:…)`, `a\|b` |

**Не поддерживаются** (явно сообщают об ошибке): `\b`, обратные ссылки `\1`,
проверки `(?=…)`, `(?!…)`, `(?<=…)`, именованные группы, inline-флаги `(?i)`.

Ограничения: значения квантора ≤ 10 000, размер программы ≤ 100 000 инструкций,
бюджет поиска — 20 млн шагов (дальше — сообщение о ресурсоёмкости, а не подвисание).
